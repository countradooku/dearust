Pinned dependency scope inventory
================================

Run (Python 3 and Git only):

  python3 tools/dependency_inventory.py /path/to/upstream \
    --object-cache /path/to/dependency-objects \
    --output dependency-inventory.json

The default run never uses the network. It reads pinned commit/tree/blob objects,
not HEAD or working files, including locally initialized submodule object stores.
Its output has no checkout paths or timestamps. Missing exact pins remain pending
and explicitly unavailable; another checked-out revision cannot satisfy a pin.
Repositories in the optional object cache are bare repositories named the lowercase
SHA256 of the resolved repository URL, followed by '.git'. The cache is not an
implementation or a generated deliverable and need not be committed.

To obtain an explicit missing dependency pin, add (repeat as necessary):

  --fetch-path src/external/darlingserver

Fetching initializes an isolated bare cache repository and asks Git for only the
recorded commit with --depth=1 --no-tags. It does not modify upstream working files,
submodule configuration or branches. The command checks the exact commit before
inventorying. Errors abort output generation; absent trees never appear complete.
Relative URLs are resolved from the committed parent's repository URL using Git
submodule rules. A nested dependency can be fetched after its parent in the same
command by supplying parent first, then nested --fetch-path arguments.

The committed dependency-inventory.json is an incremental snapshot, not a claim
that all external sources are now inventoried or migrated. To reproduce its fetched
set from an empty cache, take its dependencies with availability "inventoried",
sort their paths by depth then name, and pass each as --fetch-path. cctools-port
was already locally initialized for the recorded run; it can also be fetched at
its recorded commit using the same option. New local object availability may
legitimately expand the next snapshot; unchanged object availability yields the
same JSON bytes. There is no dependency-on-current-branch behavior.

Each available tree includes every committed leaf with Git mode, type, object ID,
size and migration category/status. A dependency's path plus its entry path gives
the qualified source path. Nested gitlinks remain entries in their parent tree;
their full contents are separately inventoried when available. Counts therefore
include parent gitlinks as well as expanded child entries. Symlinks are preserved
as mode 120000 blobs, and never followed. One exact-pin xnu errno source is partial with a verified native C ABI slice;
all other 265,802 entries remain pending. The original dependency and Darwin
link/consumer gates remain incomplete.

License filename candidates include regular committed LICENSE, LICENCE, COPYING,
COPYRIGHT, NOTICE and APSL prefixes, with Git blob IDs, byte sizes and SHA256 hashes
of actual contents. This is evidence for review, not a legal classification.
Embedded source notices, exceptions, generated files, and file-specific terms
still require review; zero license candidates does not mean no license applies.
Missing and recursively unavailable pins remain in the full migration scope.

Hermetic regression suite:

  python3 -m unittest discover -s tools -p 'test_dependency_inventory.py' -v

The tests use local committed fixtures to verify partial-source pin gating,
nested traversal, exact pin
matching, working-tree/HEAD independence, committed license hashing, deterministic
output without local paths, URL resolution and rejection of inconsistent module
metadata. They do not fetch repositories or treat inventory as runtime testing.

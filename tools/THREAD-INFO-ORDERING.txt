Thread-info join/termination regression
======================================

The immediate post-pthread_join ESRCH assertion was invalid. Pinned libpthread
f07f265bfbcf071c1adfc808de971e053ea5edc5 publishes its exit gate and wakes a joiner
before __bsdthread_terminate enters native termination. A proc thread-info query
can therefore still observe the native thread. This ordering is source evidence,
not a claim of execution on an independent macOS installation.

The owned loader27-delayed-exit adds a 50ms scheduling pause at native termination
entry. Both same-candidate guest slots reproduce the old assertion failure with
a valid112-byte reply and errno0. The original source, executable and failure
reports remain preserved. No installed loader or original probe was overwritten.

The corrected fixture checks valid records and exact output bounds while the
thread exists, then requires ESRCH with the entire output untouched. Its five-
second bound catches failure to retire the native thread. All preceding ABI,
buffer/error, CPU, thread identity/name and executable-path checks remain.

Both corrected slots pass with the normal loader and delayed loader. A logging-
only companion observes45/44 valid post-join records followed by ESRCH. Expected
stdout remains the independently retained original golden, not generated output.

Implemented runtime slices
--------------------------
New no_std crates dearust-fchmod, dearust-ftruncate, dearust-fsync and
dearust-fdatasync replace four original x86_64 descriptor-only C sources.
The extra sys_fsync_nocancel export is retained alongside sys_fsync. Original
pinned/matching C sources and headers are byte-identical. Original attribution
and GPL licenses are retained; each crate documents its narrow unsafe boundary.

Linux x86_64 syscall numbers 91/77/74/75, signed descriptor/mode extension,
full signed 64-bit truncate length, zero unused argument slots and original C
int result narrowing are preserved. Negative errors convert exactly once to
Darwin errno. Descriptor validation remains in Linux; there is no path/atfd
resolution, allocator, cache or caller-buffer access. No new upstream defect
is claimed for these four original wrappers.

The original C wrappers have no cancellation hook or EINTR retry. fsync simply
delegates to its nocancel implementation. Rust preserves that behavior, while
original generated guest stubs retain their distinct cancellation/cerror paths.
Synthetic native EINTR inputs check single-call propagation; this does not
establish end-to-end thread cancellation correctness. i386 split arguments and
clean pinned runtime startup remain outside the verified scope.

CPU and memory evidence
-----------------------
All four native Rust objects import only linux_syscall; they add no allocator,
standard library, panic runtime, TLS lookup or path storage. Generated native
original and Rust functions each have zero explicit local stack subtraction
and one eight-byte push for the raw syscall's seventh argument/alignment slot.
Return addresses and callees are excluded; this is not a zero-stack/RSS claim.
Both fsync exports share the same Rust body. Native object file sizes:
                       original C       Rust
    fchmod                1208 B       1488 B
    ftruncate             1216 B       1488 B
    fsync                 1400 B       1504 B
    fdatasync             1216 B       1472 B

These include object metadata. The complete matching mixed dylib file grew
2720 bytes (871872 -> 874592 bytes) versus the previous Rust kernel. File sizes
are not loaded/resident memory measurements. Error conversion is inlined.

Native fchmod -> ftruncate -> fsync -> fdatasync roundtrip median CPU was
1398.0735 -> 1400.7335 ns: 0.19% higher, with overlapping quartiles. Twenty-one
alternating samples, 2000 rounds/sample on one eligible CPU. Original source
files remain unchanged; native header/raw-syscall adapters and all raw records
are preserved. This excludes the matching C entry's tracing wrapper.

Actual matching guest workload, previous/new/new/previous process order,
42 samples per variant, 200 rounds/sample: CPU 2.1525 -> 2.1100 us/roundtrip,
1.97% lower median; quartiles 2.115..2.185 vs 2.100..2.130 overlap. Wall medians
2.155 -> 2.115 us. These warm repeated operations do not add new file contents
between rounds. This is not durable-write throughput, general application
performance or process-RSS evidence. No broad performance improvement is claimed.
Historical permission/path measurements remain separate evidence.

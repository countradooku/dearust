Completion status
------------------
This is validated partial migration work, not a completed resource subsystem.
The full unsigned Darwin limit domain cannot be represented by the current
stateless Linux backing, and measured CPU costs exceed original C materially.
The completion gates remain OPEN. Passing functional tests does not waive them.
No universal speedup, complete XNU policy, installed update or target retirement
is claimed. runtime-resources-verification.json records the exact final evidence.

Implemented and verified scope
--------------------------------
getrlimit, setrlimit and getrusage join the existing dearust-process subsystem
under resources, alongside identifiers in process-ids.o. Both full relinkers keep
--process-ids-object and replace the three original misc C inputs exactly once.
The original rlimit_bsd_to_linux helper is preserved too. There are13 globals:
12 private, plus the intentionally public sys_thread_selfid. queries-only
process.o is unchanged. No new crate, allocator, runtime object or export is added
to the final public dynamic symbol set. paths.o adds private fixed-copy helpers.

ABI authority is pinned XNU fa29287aa2f0115271e091f1031f53c9e024005d,
bsd/kern/kern_resource.c and bsd/sys/resource.h; original Darling wrappers are
at superproject60ba801decee7a00782f74f6be4c8ffb013f79ff. Compiled SDK oracles
establish rlimit16 on both input ABIs, rusage144 on x64 and72 on i386. This Rust
runtime slice remains x64 LP64; original i386 is retained byte-identically.
The erroneous original conversion header's176-byte dummy rlimit is not guest ABI.
fd.o getdtablesize now uses16 bytes and reads the same actual NOFILE policy.

Exactly16 bytes are copied in before setrlimit validates resource or values.
getrlimit validates resource/query before output; backend failure cannot write
output. getrusage validates SELF0/CHILDREN-1, excluding LinuxTHREAD1, before access.
The POSIX0x1000 flag is masked for selecting nine BSD resources, which map to
Linux0,1,2,3,4,9,8,6,7. AS/RSS uses address-space policy, not ignored Linux RSS.
All guest pointers remain raw; invalid mappings produce errors rather than Rust
references, unbounded dereferences or converter crashes. All padding is defined.
Darwin LP64 timeval has seconds64, usec32 and zero padding32. Linux uses two64-bit
members. Owned rusage is converted in place: retain usec low32 and clear padding;
convert maxrss KiB to bytes using defined wrapping native-long arithmetic. Other
counters retain their values. No second144-byte output array/copy is required.

The old NOFILE +/-1 policy served a disabled LKM driver relocation block in
emulation/src/other/mach/lkm.c. Current dserver descriptor management does not
perform that reservation. Both get and set now use actual host limits, with no
zero underflow, infinity increment or phantom descriptor. Child-only NOFILE0/1,
full tables, inheritance and getdtablesize checks prove the new coherent behavior.
There is no new descriptor, cache, lock, permission delegation, cancellation hook
or generic retry in the resource wrappers.

Fixed-copy infrastructure
--------------------------
paths.o supplies strong private dearust_copyin/out. Exact binary copyin uses a
new recovery PC, separate from NUL-terminated pathname loads. Existing guarded
readiness,40-byte stack, AC/mask checks, Mach-O alternate-entry atoms and async
abort-before-dispatch rules remain. The kernel fallback blocks catchable signals
across fresh PID lookup/process_vm transfer and restores the exact prior mask;
restoration failure fails stop. No guest address becomes a Rust slice/reference.
Both helpers require unsafe Rust callers with ownership/aliasing/local-storage
contracts; invalid mappings remain valid error cases. Production links contain
no weak fallback stubs. Weak abort adapters exist only for native tests of
unrelated functions and are overridden by strong resource-fixture adapters.
See crates/dearust-process/SAFETY-RESOURCES.txt and dearust-path/SAFETY-MEMORY.txt.

Open semantic gates
--------------------
Darwin RLIM_INFINITY=i64MAX, Linux RLIM_INFINITY=u64MAX. XNU's rlim_t is unsigned;
its common setter does not reject every finite value above its infinity sentinel.
It is impossible to preserve all values and soft/hard ordering with a stateless
scalar sentinel translation. Swapping sentinels is not correct: it can invert
an otherwise valid pair. An unsynchronized cache loses state/order under threads,
fork/exec and external host limit changes; unrelated limit slots cannot be used
as hidden storage. A broader resource ownership/lifecycle strategy is required.

Current defensive behavior avoids silent corruption: first reject guest soft>hard
with EINVAL. Reject finite guestu64MAX or translation-induced pair inversion with
EOVERFLOW before mutation. Preserve other representable high finite pairs. Query
rejects finite Linuxi64MAX or guest-order inversion with EOVERFLOW before output.
These representability errors are deliberate containment, NOT exact-XNU success
semantics. The gate stays unfinished until valid unsupported inputs are handled
correctly, not merely documented or falsely treated as infinity.

Enforcement and accounting still come from the caller's Linux resource policy.
This batch does not port XNU CPU timer/immediate-SIGXCPU management, main-stack
mapping/protection/maxsmap rules, maxdmap/maxproc clipping or Mach wire-limit
ownership. Resource-specific observable policy belongs in the same unfinished
compatibility work; direct prlimit is not proof that XNU semantics are complete.

Performance gate
------------------
The reproducible native and actual guest workload queries CORE, sets its unchanged
value, then reads SELF usage. C and Rust preserve the same host effects; original
C still omits correct Darwin infinity/layout/unit conversion and fault handling.
The C guest reference compiles exact pinned sources/common base.h with matching
flags in owned outputs, bypassing local matching trace instrumentation. Both
variants use the same paired server and guest binary. All raw samples, tails,
first measured rounds, memory distributions and failed comparisons are retained.

The guarded route adds a Linux mask query per fixed copy. The three-call round
therefore has three resource syscalls plus three mask queries; original C has
three resource syscalls and unsafe/direct layout handling. Forced kernel copy
adds block/getpid/transfer/restore per copy. Native and guest timings independently
show a material CPU cost. Clearing that gate requires a proven ownership/signal
strategy or equivalent exact safe mechanism, not skipping mask checks, assuming
stable mappings, caching stale masks/PIDs or weakening invalid-pointer tests.
In-place rusage conversion removed avoidable local buffer copying and reduced
stack; it does not remove the signal-safety syscall requirement.

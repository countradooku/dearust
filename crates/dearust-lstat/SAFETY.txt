lstat and lstat64: narrow x86_64 runtime migration
================================================

Source: xnu darling/src/libsystem_kernel/emulation/src/xnu_syscall/bsd/impl/stat/lstat.c
at fa29287aa2f0115271e091f1031f53c9e024005d, GPL-3.0-or-later.
Replaces both exported wrappers, preserving vchroot expansion with flags=0,
per-thread cwd lookup, Linux x86_64 raw lstat syscall 6, negative Darwin errno,
and the existing stat_linux_to_bsd/stat_linux_to_bsd64 conversion routines.
These converters retain the existing uid/gid policy and Darwin structure layouts.
No allocator, host OS mutex, Rust standard library, or panic runtime is linked.

Confirmed upstream defects fixed:
- sys_lstat64 previously copied a NULL path without checking it, crashing bsdtar
  during archive_read_disk_entry_from_file. Both wrappers now return -EFAULT.
- Both original wrappers used unbounded strcpy into a 4096-byte stack path.
  Both now return Darwin -ENAMETOOLONG if no NUL occurs within those 4096 bytes.
- NULL output pointers now return -EFAULT instead of crashing in conversion.

The safe path module initializes and copies at most 4096 bytes, stops immediately
at NUL, accepts a terminator in the last slot, and preserves arbitrary byte paths.
Unsafe operations are isolated in abi.rs. A non-NULL path must be readable through
its terminator or 4096 bytes, whichever is shorter. Non-NULL output pointers must
be writable, aligned Darwin stat/stat64 structures, with no conflicting access.
Arbitrary non-NULL invalid addresses are not newly made fault-safe by this port;
that remains a broader syscall-emulation boundary limitation.

Expanded is repr(C), matching char[4096], uint32 flags, int32 dfd. LinuxStat is
144 bytes aligned to eight, matching the kernel and original conversion header.
The raw syscall owns writes into this initialized buffer. Converters run only
after success, so errors leave caller output untouched. Foreign callees must not
unwind into Rust. vchroot_expand must preserve a NUL-terminated path on success.

get_perthread_wd is an inline C accessor over guest pthread TLS, not a linkable
symbol. The sole bridge in tools/fixtures/lstat-bridge.c exports it as hidden
int dearust_get_perthread_wd(void), compiled against the original headers using
exact original emulation flags by tools/build_lstat_bridge.py. Production calls
require initialized Darling thread/TLS state; the bridge avoids copying hardcoded
TLS keys into Rust. This is a partial source migration due to retained conversion,
virtual-root and TLS boundaries. Only x86_64 has been validated.

Verification: three safe-path tests; exact ELF/Mach-O exports/imports and private
visibility in xtask runtime tests. The native C fixture lstat-native.c exercises
both wrappers against real Linux lstat for files/symlinks, null pointers, long
paths, missing paths, expansion errors, and output preservation. It explicitly
adapts TLS/vchroot and records Linux metadata instead of pretending to implement
guest conversion. Guest app probes and bsdtar tests validate actual Darwin structs
and expansion separately. Build the bridge with --build ORIGINAL_BUILD --output
NEW_DIRECTORY, and pass both objects to the matching runtime relinker.

Performance continuation: the safe copier fills initialized Expanded.path in place,
rather than returning a 4096-byte array through Result and copying that array into
Expanded. NULL validation still precedes copying; bounded copying still precedes
all descriptor/TLS, virtual-root and syscall boundaries. Copying stops at NUL and
leaves the initialized suffix untouched. No uninitialized storage or new unsafe
operation is introduced. Native release assembly removes the full-array memcpy
and reduces local stack allocation by about 8 KiB per wrapper invocation. The
4096-byte zero initialization is deliberately retained for the foreign boundary.
Tests also verify untouched destination suffix and exact capacity bounds.

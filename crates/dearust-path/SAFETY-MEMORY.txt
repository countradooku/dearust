Fault-contained guest addresses: x86_64 LP64
==========================================

This document supersedes historical raw guest-pointer and kernel-copy-only
contracts in SAFETY.txt and SAFETY-FSTAT.txt. Original Darling authorship,
pinned-source attribution and licensing continue to apply.

Guest addresses never become Rust references. All pathname inputs and all eight
metadata copyouts use abi/memory.rs. The default optimization is a bounded leaf
assembly copy in abi/guarded.rs, integrated with the existing Darling Linux
signal entries; it does not replace process-wide handlers for individual calls.
The runtime owns these entries. Native libraries must preserve the installed
Linux signal hooks, as required by Darling's signal/RPC machinery generally.
Native code may change signal masks: the copy queries the actual kernel mask on
EVERY invocation. No cached mask, PID, mapping, or address-range proof is used.

The leaf uses volatile registers and one forty-byte stack allocation. Every PC
in its recovery region has exactly that frame. Mach-O alternate-entry labels
keep the region and recovery stubs in the same linker atom. Before entering the
region it checks RFLAGS.AC; alignment-checking callers use the kernel fallback,
preserving valid unaligned addresses and the caller's AC flag. Within the region
raw Linux rt_sigprocmask14 queries the current eight-byte mask. Query failure or
blocked SIGBUS7/SIGSEGV11 chooses the kernel fallback before guest access.

Path storage is [MaybeUninit<u8>;4096]. Only the copied prefix through NUL
becomes initialized; Rust never forms byte references to its unused suffix.
C expansion helpers must inspect only that terminated prefix, as their original
strcpy-based callers also require. This removes repeated4096-byte clears without
weakening the initialized-memory contract. Path input is read one byte at a time,
stopping at NUL or4096 bytes. The exact
guest-load PC is recoverable. Metadata output uses bounded four-byte stores from
initialized local storage, with one recoverable guest-store PC; supported120/144
byte layouts are multiples of four. Nonmultiples of four choose the fallback.
A third exact guest-load PC supports fixed binary input without NUL scanning.
Positive-code synchronous SIGSEGV/SIGBUS at those exact three PCs redirects to
EFAULT. Synchronous faults elsewhere retain ordinary dispatch. Other signals
inside the region redirect to a retry stub BEFORE ordinary signal/RPC delivery;
a handler cannot fork or change masks and then resume an obsolete copy proof.
No unwinding, Rust longjmp, mapping preflight or unguarded guest access is used.
Concurrent unmapping/reprotection therefore causes a contained access fault.

Copied original sigexc.c and sigaction.c units install the early PC hook in all
three supported entry paths: sigexc_handler, sigrt_handler, and the direct
SIGCHLD/SIGTTOU wrapper. A conservative atomic installation state publishes
readiness only after successful standard-handler/initial-altstack and both RT
handler installations. Missing/failed readiness chooses the kernel fallback.
Signal handling retains ordinary dispatch, including unrelated synchronous
faults. Stored Darwin masks are converted before Linux use and unioned with the
interrupted mask; SA_NODEFER is tested in the Darwin flag domain. Signal RPC exit
is paired with the Linux process that entered: a newly checked-in fork child
must not pop its parent's server interrupt frame. Positive raw Linux PID queries
establish that process identity; query failure is fatal rather than a false match.

Copied generated RPC wrappers bind each transaction to a process-local epoch.
After handler fork, the child's signal epilogue advances that epoch and redirects
an interrupted/restarted no-stack syscall leaf to cancellation. Abandoned sends,
receives and S2C memory operations cannot act on the fresh child server connection.
Already completed ordinary replies retain their fork snapshot. Ancillary receive
storage is initialized/reset on every retry, and abandoned SCM_RIGHTS ownership
is closed exactly once, including S2C ownership transfer. Native full signal masks
are saved/restored, retaining RT bits; block/restore failure fails stop. The RPC
leaf's return PC is outside its recovery region and Mach-O alternate-entry labels
keep all recovery PCs in one atom. The original RPC protocol is unchanged.

Fallback copies use process_vm_readv310/process_vm_writev311. All catchable
signals are blocked across fresh getpid39, every transfer, and completion. This
closes the getpid/handler-fork stale-parent-PID window. The exact previous mask is
restored before returning. Block failure returns a converted error. Restore
failure terminates with raw exit_group231 with status127 (UD2 if exit_group itself is denied),
rather than continuing with a corrupted mask. There is no unsafe raw fallback.
Two LP64 repr(C) iovecs are sixteen bytes each and point to live initialized
local storage (uninitialized destination bytes remain MaybeUninit). A Rust byte
slice is formed only over the exact kernel-reported initialized prefix. Path fallback first reads at most64 bytes; if nonterminated, a
checked integer address addition reads the remaining4032. A partial readable
prefix containing NUL succeeds; other partial reads return EFAULT. A full4096
bytes without NUL returns ENAMETOOLONG.

Metadata Linux buffers are initialized144-byte locals. abi/conversion.rs forbids
unsafe code and translates only those local bytes to actual Darwin stat120/stat64
layouts. Original __getuidgid obtains the process credential pair under one lock;
there is no new credential cache. All output bytes, padding and reserved fields
are assigned deterministically, with reserved/birth fields zero. Original C
converters used by unported callers remain in place. Rust conversion is checked
against unchanged pinned C conversion source with initialized reserved bytes,
including extreme/narrowed fields, and SDK field offsets/sizes independently.
The expansion bridge may return the Linux metadata fetched for the actual last
ordinary non-symlink component within this same invocation. It creates no cache.
Only valid0/AT_SYMLINK_NOFOLLOW flags may reuse that snapshot; flag validation
retains its original ordering, and every other case executes the final stat.
Only the exact120/144-byte output is copied. Faulting copyout may modify a prefix
before EFAULT; no atomic rollback is promised. fstat kernel errors keep precedence
over output access. Existing pathname/TLS/error ordering remains in force.

Unlink expansion may keep a simple, exact existing nofollow basename relative
to its original directory fd through the final kernel unlinkat. This avoids the
/proc/self/fd readlink and does not follow a newly substituted final symlink.
All errors, case-folding work, complex paths and virtual-root transitions use the
full resolver. The fast path allocates no descriptors or persistent state.
Copied resolver bounds checks also cover long roots/paths/symlinks, prefix tests,
fdpath output capacity and dot/dotdot directory semantics. Root updates stage
validated local state, obtain server approval, then commit the local prefix;
validation or RPC rejection leaves the previous prefix unchanged. Existing C
namespace/lifecycle contracts are retained; this is not a whole-resolver port.

Unsafe boundaries are foreign ABI calls, local Linux-stat reference construction,
and the documented assembly leaf. C helpers must obey ABI, not unwind or retain
local pointers, remain within buffers and preserve pathname termination. Guest
output must not alias live wrapper storage. This shared address-space runtime
cannot isolate malicious valid addresses targeting its own implementation; this
is not a whole-runtime memory-isolation claim. Unported C remains outside Rust's
memory-safety guarantees. Supported Rust runtime target remains x86_64 LP64.

Regression coverage includes all exported pointer cases in guarded and forced
fallback modes; unmapped/PROT_NONE/read-only and page-end inputs; exact ABI tails;
SIGBUS mappings; unrelated faults; mask preservation and nested handlers;
restore-failure fail-stop; AC preservation; deterministic native interruption
with handler fork; concurrent mprotect revocation; and actual Darwin guest
signal/mask/concurrency/fork execution. Native fixtures use real Darwin-layout
adapters. ASan/UBSan cover C fixtures/adapters, not the existing Rust/assembly
objects. No allocation, leak, RSS, universal compatibility or regression-free
performance claim follows from these tests; performance has its own measured
completion gate, which remains unfinished while a material slowdown is present.

Resource fixed binary copies
----------------------------
The runtime now exports strong private dearust_copyin(local,guest,length) and
dearust_copyout(local,guest,length). Both are unsafe Rust APIs with explicit
local initialization, ownership/aliasing and foreign ABI contracts; the helper
never forms a reference over a raw guest address. Two compile-fail checks cover
these contracts. Resource callers use exactly16/144 initialized local bytes.
Copyin guarded mode2 uses a distinct guest dword-load label; its local store is
not recoverable. Other lengths use exact-count kernel fallback; zero lengths
succeed before inspecting either address. Existing40-byte recovery stack,
Mach-O alternate-entry atom, AC/mask checks, asynchronous abort before ordinary
dispatch and handler-fork/PID rules are retained. Native fixtures exercise
lengths0/1/3/4/8/16/144, embedded zeros, protected/readonly/cross-page/unaligned
addresses, both boundary modes, signals and fork. These helpers introduce no
unsafe fallback. Their current CPU cost remains a visible unfinished resource
completion gate; see RUNTIME-RESOURCES.txt.

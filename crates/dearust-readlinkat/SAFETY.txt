readlinkat: bounded, allocation-free x86_64 runtime migration
===========================================================

Source: xnu darling/src/libsystem_kernel/emulation/src/xnu_syscall/bsd/impl/unistd/readlinkat.c
at fa29287aa2f0115271e091f1031f53c9e024005d, GPL-3.0-or-later. Exact pinned
and locally matching C files are byte-identical. Original Darling/upstream
attribution and licenses continue to apply. Safe bounded copier derives from
this project's dearust-symlinkat path module under the same license.

Original atfd and vchroot_expand remain C boundaries: flags=0 prevents following
the final link; atfd preserves BSD_AT_FDCWD (-2)/per-thread cwd. Raw Linux x86_64
readlinkat syscall 267 receives the expanded descriptor/path and unchanged caller
buffer. The original signed int count is sign-extended to the syscall ABI.
Its result is narrowed to int as in C then converted to negative Darwin errno.
No NUL is appended and truncation returns the actual byte count. Invalid output
pointers, zero/negative count and path/output error ordering remain kernel or
expansion decisions; Rust does not eagerly reject an output pointer.

Confirmed unbounded strcpy is replaced with at most 4096 byte reads directly
into an initialized Expanded, avoiding a returned/copied 4096-byte path array.
NULL path returns Darwin -EFAULT; no NUL in 4096 bytes returns -ENAMETOOLONG.
Non-NULL path must remain readable through NUL or 4096 bytes, whichever is first.
Arbitrary invalid non-NULL paths are not made fault-safe. Kernel output memory
must not alias Rust's live stack; Rust creates no references to caller output.

Unsafe is confined to abi.rs: pointer reads, exported contract and foreign calls.
Expanded repr(C) is char[4096], uint32 flags, int32 dfd. Expansion must preserve
termination on success; helpers must not unwind. atfd needs initialized guest TLS.
No allocator, std, mutex, panic runtime or hardcoded guest TLS key is introduced.

Scope is partial, x86_64 only. Native fixture uses explicit vchroot/TLS adapters
and real Linux syscalls; guest fixture separately exercises actual Darling paths,
working directories, output bytes, truncation and error propagation.

fstatat and fstatat64: narrow x86_64 runtime migration
====================================================

Source: xnu darling/src/libsystem_kernel/emulation/src/xnu_syscall/bsd/impl/stat/fstatat.c
at fa29287aa2f0115271e091f1031f53c9e024005d, GPL-3.0-or-later. The pinned
and locally matching source files were compared byte-for-byte and are identical.
Original Darling/upstream attribution and licensing continue to apply. The safe
path module is copied from dearust-lstat in this project, under the same license.

Both ABI exports use original atfd, atflags_bsd_to_linux, vchroot_expand and
stat_linux_to_bsd/stat_linux_to_bsd64. BSD_AT_SYMLINK_NOFOLLOW (0x20) selects
no-follow expansion; otherwise VCHROOT_FOLLOW (1) is preserved. Flag conversion
occurs AFTER expansion exactly as in C, including errors and the existing policy
accepting/ignoring some flags. No claim of new Darwin flag-policy support is made.
The expanded dfd and path feed Linux x86_64 newfstatat syscall 262, preserving
negative Darwin errno conversion, descriptor-relative paths and thread cwd via
the original atfd helper. No TLS bridge or hardcoded guest TLS key is introduced.

Confirmed source hazards addressed: unbounded strcpy into char[4096] is replaced
by copying at most 4096 bytes, rejecting unterminated input with -ENAMETOOLONG.
NULL output now returns -EFAULT before expansion or conversion, rather than
crashing when converting a successful stat. NULL path still returns -EFAULT.
Non-NULL invalid addresses are not made fault-safe by this migration. Such paths
must be readable through NUL or 4096 bytes (whichever is shorter). Non-NULL output
must be a properly aligned, writable Darwin stat/stat64 of the matching ABI,
with no conflicting accesses. Errors leave caller output unmodified.

Unsafe is confined to abi.rs: raw pointer byte reads, foreign calls and exported
ABI contracts. Expanded is repr(C) char[4096], uint32 flags, int32 dfd. LinuxStat
is 144 bytes aligned to eight; raw kernel output is initialized before the call.
Foreign code must not unwind into Rust; vchroot must preserve NUL termination on
success. Production atfd calls require initialized Darling thread TLS. The crate
is no_std with no allocator, OS mutex or panic handler/runtime.

Scope remains a partial source migration: converters, virtual-root expansion,
descriptor/TLS conversion and common flag policy remain original C. Only x86_64
is supported. tools/fixtures/fstatat-native.c explicitly adapts vchroot/TLS and
conversion to test raw Linux boundary behavior; it does not validate Darwin
layouts. fstatat-regression.c exercises real guest wrappers/layouts separately.

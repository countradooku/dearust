faccessat: bounded x86_64 descriptor-relative runtime migration
=============================================================
Source: xnu darling/src/libsystem_kernel/emulation/src/xnu_syscall/bsd/impl/unistd/faccessat.c
at fa29287aa2f0115271e091f1031f53c9e024005d, GPL-3.0-or-later. Original
Darling/upstream attribution and licenses apply. Pinned/matching C are identical.

One initialized repr(C) Expanded holds final char[4096], uint32 flags and int32
fd. Safe copying writes directly into this storage without intermediate arrays
or heap. NULL yields Darwin EFAULT, fixing original strcpy crash; missing NUL in
4096 bytes yields ENAMETOOLONG. Non-NULL input must remain readable through NUL
or 4096 bytes; arbitrary invalid non-NULL pointers are not made fault-safe.

Unsafe is confined to abi.rs pointer reads, export and foreign calls. Original
atfd preserves initialized guest TLS/per-thread cwd. vchroot_expand follows the
final symlink except when BSD_AT_SYMLINK_NOFOLLOW (0x20) is set. It must preserve
termination; helpers must not unwind. Original C atflags conversion runs AFTER
expansion and returns EINVAL on sentinel 1. Raw Linux faccessat 269 receives
signed mode and the original fourth flags slot, with exact int result narrowing.
Linux faccessat ignores this fourth slot: effective-credential flags and final
nofollow semantics are NOT fully implemented by this port. Original converter
also does not implement EACCESS policy. This existing limitation is preserved;
there is no faccessat2 switch or newly invented Darwin credential policy.

No allocator, std, panic runtime, cache or mutex is introduced. Scope is partial,
x86_64 only. Native fixture uses explicit path/TLS adapters and actual Linux
syscalls; guest fixture separately exercises actual Darling path handling.

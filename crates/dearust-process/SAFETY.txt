Darling process-query Rust slice (x86_64 Linux/Darling only)
=========================================================
The exported sys_proc_info replaces the original dispatcher. Compile the pinned
or matching-local proc_info.c with -Dsys_proc_info=darling_legacy_proc_info and
link it alongside this object. Unported queries still execute that original C
implementation. This is a partial migration, not a replacement for all libproc.

Rust implements LISTPIDS (all, process group, terminal, effective/real UID,
parent), PIDLISTFDS, PIDLISTTHREADS, PIDVNODEPATHINFO and PIDFDVNODE[PATH]INFO.
PID enumeration uses procfs in the running caller's PID/mount namespace and
only includes registered Darwin tasks. Existing Mach task-name rights and
TASK_AUDIT_TOKEN supply simulated credentials; every acquired right is released.
Darling currently has one simulated UID used for getuid and geteuid: both UID
filters follow that representation, not unrelated Linux credentials. Process
exit/races between enumeration and queries are normal, not atomic snapshots.

parse.rs contains only safe Rust. abi.rs narrowly owns raw Linux syscalls, C/MIG
calls and final copies to caller-provided buffers. The syscall entry contract
requires buffer to be null or a valid exclusively writable allocation of at least
bufsize bytes; arbitrary inaccessible nonnull pointers are not recoverable by
Rust, matching the existing in-process emulation convention. Negative sizes are
rejected before conversion. Record writes are bounded and never partial. All
local buffers are initialized; procfs parsers reject malformed lengths and
arithmetic overflow. Raw kernel writes receive the correct live array lengths.
Linux x86_64 stat offsets and Darwin fixed vinfo ABI layouts are explicit. The
buffer API avoids references or aligned accesses into foreign caller memory.

Raw syscalls use Darling's seven-argument linux_syscall ABI and translate Linux
errors once. Read/getdents retry EINTR. Temporary descriptors have O_CLOEXEC and
RAII cleanup. No allocator, Rust panic handler, standard library, thread-local
storage or unwinding is introduced. Existing linked C/MIG boundaries must not
unwind into Rust. Directory/path queries use original vchroot_unexpand, and
open flag conversion reuses oflags_linux_to_bsd.

No all-process atomic snapshot is promised. Linux lacks Darwin birthtime,
vnode-generation and guard metadata: unavailable fields remain zero, as in the
existing port. i386, cancellation and inaccessible-pointer recovery are untested.
Other unported legacy flavors retain existing behavior and limitations.

Follow-up behavior verified with the actual mixed runtime
--------------------------------------------------------
TBSDINFO fills pbi_name from the registered executable path, fixing proc_name
returning the Linux loader name. Its remaining fields now use the Rust BSD
implementation described below. REGIONPATHINFO and the
file-backed REGIONPATHINFO2/3 queries parse bounded /proc/maps records into fully
initialized structures; no-match errors never copy uninitialized memory. The
file-backed variants skip anonymous mappings and return EINVAL at end of search.

All proc paths pass through vchroot_expand to the namespace's guest proc mount.
For stat/readlink, the final procfs magic link is left for the Linux kernel to
resolve: user-space resolution would prepend the guest prefix twice. Linux
expansion errors are translated to Darwin errno. Path-unexpansion inputs reserve
space for the original C implementation's host-path prefix expansion.

Overlayfs mapping records expose backing devices unlike guest stat. For a mapped
path that still names the same inode, querying that path recovers the overlay
identity used by libproc's stat comparison. A path replaced by another inode is
never substituted. Unlinked or inaccessible mappings retain their procfs identity;
matching deleted overlay mappings by pathname is not guaranteed. Vnode ownership
uses the same simulated uid/gid presentation as existing stat_linux_to_bsd64.
Darling's existing single-identity ownership model is preserved, not broadened.

The actual C probe covers PID filters and sizing, invalid filters, negative and
short-buffer canaries, thread lists, vnode ABI sizes, fd identity/path/offset,
FREAD/FWRITE flags, cwd/root queries and both open-fd and mmap-only path matches.
Original libproc.c passes all six checks in the Rust mixed runtime. Tests use
an isolated matching server and guest prefixes; no installed runtime is modified.

BSD and task-info follow-up
--------------------------
SHORTBSDINFO (13), TBSDINFO (3), TASKINFO (4) and TASKALLINFO (2) now execute
Rust, with fixed C layout sizes 64, 136, 96 and 232. No fields from these flavors
are delegated to the C implementation. The pure info.rs module parses stat
records (including embedded ')' and newlines in comm), performs checked unit
conversion, and emits fully initialized fixed-size records. Invalid/truncated
records and conversion overflow fail before caller memory is changed. Failed
TASKALLINFO is transactional; larger caller buffers retain their unused tail.

Existing TASK_AUDIT_TOKEN supplies the queried task's current virtual UID/GID,
not a cached caller identity. Darling currently models only one UID and GID:
real/saved fields repeat that value, consistent with its getuid/geteuid model.
The task_is_64_bit RPC receives a live C-bool output. native_sysconf takes scalar
Linux _SC_CLK_TCK (2) and _SC_PAGESIZE (30) selectors; both existing C boundaries
must return normally without unwinding. Only their validated positive results
are used. No extra allocator or panic runtime is linked. /proc/stat boot time
is read incrementally, independent of the host's CPU-count/file length.

The public PROC_FLAG_LP64 bit is 0x10 (not kernel P_LP64=4, which erroneously
advertises PROC_FLAG_INEXIT). RSS is converted from Linux pages to bytes; CPU
USER_HZ ticks become Darwin x86_64 nanosecond absolute-time units. Fault counts
saturate at INT32_MAX like XNU. Start seconds/microseconds use boot epoch plus
start ticks. Negative priority/nice are retained. Negative transient RSS is
clamped to zero. Architecture and unobservable scheduling/IPC fields retain
existing limitations: only LP64 among BSD flags is modeled; task policy, live
thread CPU totals, COW faults, IPC/syscall/switch counts and running-thread count
remain zero rather than invented. Priority still reflects Linux scheduling.
This is not a claim of full Darwin task-accounting equivalence.

Source contracts: pinned xnu bsd/sys/proc_info.h (fixed layouts and public flags),
bsd/kern/proc_info.c (short BSD return size and credentials), osfmk/kern/bsd_kern.c
(fill_taskprocinfo byte sizes, absolute CPU times, saturated faults), and the
matching server duct-tape/src/task.c (virtual credential model). Legacy defects
are in emulation/src/xnu_syscall/bsd/impl/misc/proc_info.c and its
helper/misc/sysctl_proc.c next_stat_elem parser, which stops at the first ')'.

The tools/fixtures/process-info.c actual-runtime regression covers ABI sizes,
queried child credentials changing twice while caller credentials stay unchanged,
public LP64 flags, a comm containing ')', registered executable name, boot/start
time, touched resident memory, a timed CPU workload, all-info composition, and
null/negative/short/nonexistent-PID/tail canaries. The matching C baseline fails
its short-BSD return-size assertion; the Rust mixed kernel passes the full probe.
The three pure encoding tests additionally exercise overflow, signed fields,
explicit non-1000-Hz conversion and multiple target credential values.

Process task-name lookup retains the matching Darling server capability model.
It does not add full macOS UID authorization checks; host procfs access still
applies. Unregistered host PIDs are rejected as ESRCH. This is not a claim of
macOS process-query security-policy parity.

Mapped filenames with newlines
-----------------------------
Linux /proc/PID/maps represents newline bytes as the four literal bytes \012.
The region-path implementation previously passed that encoded text to stat and
returned it as the vnode path, losing the real pathname and overlay device match.
Ambiguous names now use /proc/PID/map_files/START-END readlink to obtain the
original pathname bytes. Hexadecimal addresses and decoded paths use bounded
safe storage; readlink retains the existing raw-syscall/4096-byte ownership
boundary. No exported ABI, allocator or OS import is added.

If procfs access policy denies map_files readlink, an existing literal pathname
is retained only when stat confirms the mapping inode; otherwise the documented
newline escape is decoded. That fallback cannot disambiguate inaccessible or
unlinked literal \012 names, or differently named hardlinks to the same inode.
This is a procfs representation/access limitation, not full pathname recovery.
The pure regression checks newline decoding, preservation of other backslashes,
NUL capacity and hexadecimal map-file paths. tools/fixtures/process-mapped-path.c
checks actual region address, identity and exact paths for newline, literal \012
and ordinary-backslash filenames in an executing guest.

Thread-info and executable-path queries
---------------------------------------
PIDTHREADINFO (5) now builds the entire 112-byte public proc_threadinfo locally,
returning 112 rather than the old implementation's 1. It never clears a caller's
unused buffer tail or mutates output on failure. The low 32 bits of the handle
remain Darling's Linux TID convention, also used by sys_thread_selfid and hence
libpthread's pthread_threadid_np. /proc/PID/task/TID/stat enforces process/thread
membership; task-name credentials require a registered Darwin process. This does
not implement XNU's pthread-address handle convention or PIDTHREADID64INFO.

Thread user/system USER_HZ counts become nanoseconds (XNU fill_taskthreadinfo in
osfmk/kern/bsd_kern.c). Linux R/T/t/S/I/D/Z/X/x map to public Mach running,
stopped, waiting, uninterruptible and halted states; unknown states remain zero.
Name comes from the bounded stat comm, including embedded ')' and newline bytes.
Linux comm truncation still limits name fidelity. Decayed CPU usage, Mach policy,
flags, sleep duration and Mach scheduler priorities are unavailable and stay
zero. Linux priorities are not mislabeled as Mach priorities. Exit and state
changes can race normal procfs snapshots, as with other queries.

PIDPATHINFO (11) uses the existing server executable-path RPC and original
vchroot_unexpand with full 4096-byte live local storage. The RPC result must
terminate before byte 3900, reserving conservative headroom for the original C
EXIT_PATH prefix prepend/memmove, matching the existing region-path bound.
Null/negative sizes fail;
the public 1024..4096 size contract is enforced even for direct syscall callers.
The path is copied only after NUL termination and capacity validation, including
the NUL byte. Oversized results fail rather than returning an unterminated
truncated string as the legacy strncpy path did. Existing length-excluding-NUL
return behavior is retained; proc_pidpath itself returns strlen. Caller tail
bytes remain unchanged. No exports, OS/MIG imports or allocation are added.

Region-query CPU follow-up
--------------------------
Address-based region searches filter impossible mappings before pathname
recovery and overlay metadata syscalls. Device queries still recover each file
identity; anonymous maps remain eligible for flavor8 only. No process/path
cache is introduced. Pure tests cover exclusive mapping ends, following maps,
anonymous regions and preserved device-query candidates. Actual guest probes
retain identity/path checks; the separate benchmark records workload-specific
CPU/wall samples without treating timing as a correctness golden.

Darling Rust migration: full scope, partial implementation
========================================================

Upstream: https://github.com/darlinghq/darling.git
Pinned commit: 60ba801decee7a00782f74f6be4c8ffb013f79ff

This repository currently provides Rust host tools and a native Linux
synchronization library slice. It does not yet provide
a complete Darling runtime, a replacement SDK, or a full Cargo build of Darling.
The migration scope includes every upstream library, framework, executable,
resource, SDK link and external dependency; existing stubs are not grounds for
silently deleting an ABI. Performance improvements must be measured per workload.

Reproduce the scope inventory
----------------------------

Run from this repository with a local upstream checkout at the pinned HEAD:

  python3 tools/inventory.py /path/to/darling --output migration-inventory.json

The generator requires Python 3 and Git, makes no network requests, reads committed
Git objects rather than working files, and rejects a different HEAD. It inventories
every superproject leaf exactly once, including symbolic links and gitlinks.
Directories are represented by their leaves. Deleted or untracked working files
do not change the inventory. Object IDs make each source and dependency pin
traceable. Outputs have no timestamps or checkout-dependent absolute paths.

At this pin there are 27,274 entries:

     280 CMake files
     149 external submodule gitlinks
   2,890 symbolic links
      11 scripts

There are 5 implemented source replacements: elfdep, getuuid, bsdln,
print_wrapped_elf and darling-coredump. wrapgen has a functioning safe Rust
parser/generator, but is marked partial because safe name lookup does not
reproduce all dynamic-loader policy. Native libsimple is also partial: its Linux x86_64 synchronization C ABI
and external cmpxchg helper work, including a native no_std C-linked archive.
Darling x86_64 runtime consumers now link; i386/other architectures and actual
Darwin startup remain unported/unverified. There are 27,267 pending superproject entries. Exact diagnostic text is not guaranteed. Each source replacement has
behavioral and malformed-input regressions plus a pinned differential suite.
These gates validate this Linux host slice, not the Darling runtime or macOS ABI.

The forced same-inode hard-link regression preserves an upstream-deleted source.
New regressions cover DT_SONAME at nonzero load addresses, dropped extra core
mappings, deterministic segment padding, short backing-file zero fill, destructive
output aliases and adversarial parser/mapping work. Core mapping lookup is bounded
by an ordered O((areas + mappings) log mappings) algorithm. Floating-point core
states remain zero, matching upstream's TODO; no FP extraction port is claimed.

All 149 first-level submodules and 11 nested gitlinks are now expanded at their
exact pinned commits in dependency-inventory.json. The 160 dependency trees
contain 265,803 committed leaves (two partial errno/futex source slices and
265,801 pending), and 341 filename-based
license candidates with actual blob hashes. No Git trees are unavailable in this
snapshot. The isolated baseline still contains 44 Swift Git LFS pointers;
their binary payloads have not been materialized or migrated. Regeneration is byte-identical with the same object cache; see
tools/DEPENDENCY-INVENTORY.txt and tools/dependency_inventory.py.
The errno source has a separately implemented and C-verified native ABI slice;
inventorying the remaining dependency entries does not port them. Source-category
counts use suffix heuristics; Java, Swift and other code may fall under metadata.
Every committed leaf remains in scope regardless of its category label.

The two inventories together track 293,077 entries, including parent gitlinks
and their separately expanded contents. Headers/resources may require faithful
preservation and explicit review rather than translation. No external tree,
framework, resource or ABI is implicitly waived from the full migration.

Observed build graph and baseline
--------------------------------

The isolated exact-pin original checkout configures successfully with default
CMake options on the recorded host. Original native elfdep/getuuid/bsdln/wrapgen,
darling-coredump and libsimple_darlingserver targets build successfully. The
remaining runtime has not been built or run. Forty-four Swift LFS binary
payloads remain missing even though their Git pointer objects are inventoried.

upstream-cmake-graph.json captures 1,629 emitted default targets, 7,785 dependency
edges, 34,478 source records (9,593 generated) and 1,238 targets with installation
metadata. migration-targets.json maps seven default targets to Cargo artifact
slices, including partial wrapper/native/Darling library coverage. There are 1,622
pending default targets and no claim of legacy target retirement. Optional
print_wrapped_elf is a verified extra artifact absent from the default graph.
Custom command bodies, optional component configurations and generator-specific
recipes are not fully represented by the File API and require separate gates.
The typed Cargo graph stages six tools, the native static archive and a native
errno validation object;
it is not a replacement for all 1,629 upstream targets. Reproduction scripts,
logs and reports are listed in tools/BASELINE.txt.

Migration order and executable gates
-----------------------------------

1. Reproduce upstream builds and behavior in an isolated baseline environment.
   Dependency trees are now inventoried; review file-specific licensing and
   generated inputs, and extract target, install and link graphs from CMake. Record supported architectures, host requirements, symbol
   exports and test workloads. Preserve the original checkout as reference.

2. Move host-side parsing and code generation to Cargo packages. Current metadata
   readers are a first slice. Port the remaining buildtools and hosttools, test
   valid and malformed inputs against upstream and independent binary fixtures,
   and preserve CLI exits and output consumed by build rules.

3. Add a Cargo-invoked orchestration command with an explicit artifact graph.
   Capture each CMake target's generated sources, architectures, flags, Mach-O
   install names, rpaths, exported symbols, linker scripts, framework versions,
   symlinks and installation destinations. Cargo alone does not implement Mach-O
   cross-linking, SDK assembly or framework layouts. Initially an orchestration
   layer may invoke existing tools; remove each CMake edge only after its Cargo
   equivalent produces and installs the same required artifacts. A Cargo build
   of the host utilities is not a full replacement of CMake.

4. Port pure data transformations, Mach-O/ELF parsing, archive handling and safe
   filesystem utilities. Use checked offsets, bounded slices and owned types.
   Differential tests must distinguish upstream defects from intended behavior.
   Add a regression case before changing a confirmed defect.

5. Establish reviewed ABI crates and port low-level loading, startup, vchroot,
   libelfloader, tracing, process/thread management and darlingserver/XNU-facing
   interfaces in dependency order. Preserve wire formats, syscall results, errno,
   signal behavior, virtual addresses, calling conventions and thread-local state.
   Boot and process-launch smoke tests gate higher-level runtime migration.

6. Port libSystem and dependent runtimes, including libc, libpthread, libmalloc,
   libdispatch, dyld, Objective-C, exceptions/unwinding and blocks. Expand their
   pinned submodule inventories first. Rust implementations must retain the ABI
   expected by existing C, C++ and Objective-C macOS binaries; translating API
   names or exporting a stub is insufficient. Cross-language conformance tests
   and representative unmodified macOS binaries are required.

7. Port CoreFoundation/Foundation and the complete public/private framework
   dependency graph, including third-party components, then command-line tools,
   services, UI/graphics/audio and language runtimes. Inventory entries identify
   each component; split large components into independently tested crates.
   Preserve framework metadata, Objective-C classes/selectors, resources and SDK
   links. Do not count a placeholder or missing export as a completed port.

8. Replace packaging and SDK installation rules, then exercise clean Cargo-driven
   builds and installations on every supported host/target combination without
   requiring CMake. Verify package contents, relocatability, dependency discovery
   and runtime loader behavior. Retire upstream implementation paths only when
   every corresponding target has passed its migration gate.

Safety boundaries and ABI obligations
------------------------------------

Keep parsing, policy, state machines and ownership in safe Rust. Forbid unsafe
code in those crates. Low-level adapters may need unsafe for exported C ABI raw
pointer access, mapped executable memory, foreign function calls, direct syscalls,
signal handlers, machine context manipulation, thread-local storage and assembly
trampolines. Each use needs a documented invariant, ownership/lifetime argument,
validation of sizes/alignment/provenance and a small reviewed safe wrapper.
Do not declare arbitrary foreign pointers safe merely by wrapping them in a slice.
Representations crossing ABI boundaries need explicit layout, widths, alignment,
endianness and calling conventions. Prevent Rust unwinding across incompatible
foreign boundaries and preserve the required foreign exception semantics.

Avoid claiming that all machine-level behavior can be replaced with safe Rust.
Architecture-specific glue can be necessary, but convenience alone does not
justify unsafe. Rust also cannot automatically detect a foreign caller violating
its ABI contract. Run Miri where supported, sanitizers and fuzzing at parsers and
FFI boundaries, and native target integration tests for platform behavior those
tools cannot model. Record each remaining unsafe operation and its justification.

Full-completion criteria
-----------------------

All superproject and recursively inventoried dependency entries must resolve to
a verified Rust implementation or an explicitly reviewed preserved non-code
artifact. Any surviving foreign implementation means full Rust migration is
still incomplete. Assembly/FFI glue must have documented unavoidable boundaries.
Every original build/install target and exported ABI needs a mapped equivalent;
libraries and frameworks cannot disappear from the build to satisfy this gate.

Require clean Cargo-driven builds, packaging and installation, ABI/symbol/layout
checks, upstream regression coverage, malformed-input/fuzz tests, concurrency and
process/signal tests, and representative application compatibility against a
recorded baseline. Every bug fix needs a reproducer and regression test. Report
benchmark environment, workloads, allocations, latency/throughput and variance;
do not infer performance from language choice. Full completion additionally
requires no unexplained compatibility or performance regression and no pending
inventory entries. These criteria have not yet been met.

Errno source slice and target boundary
-------------------------------------
The pinned xnu dependency's emulation conversion/errno.c now has a safe no_std
replacement. Its sparse mapping, signed/unknown-value behavior, two original
hidden globals and size_t object are checked against compiled committed C/headers.
INT_MIN overflow is fixed with a UBSan reproducer and regression coverage. Native
C linkage is verified with no unresolved runtime symbols, including alongside
the staged synchronization archive. Dependency source status remains partial
because the i386 Rust replacement and actual Darwin startup are not validated.
The x86_64 errno/futex objects and libsimple archive now participate in the actual
complete system_kernel final link. Both emulation and emulation_dyld targets remain
pending because their other sources are unported; the dyld/static variant link
also remains unverified.
No additional legacy target is retired by this native validation artifact.

Darling futex and consumer integration gates
-------------------------------------------
The new no_std futex crate preserves __linux_futex and __linux_futex_reterr over
the original seven-argument raw linux_syscall ABI, signed narrowing, pointer/
REQUEUE bits and Darwin errno side effects. The cerror binding matches its real
LP64 unsigned __int128 return, correcting the old futex declaration mismatch.
The lock backend calls __linux_futex_reterr and bootstrap __simple_abort directly.

Compiled native original guarded/table.c and full close.c execute unchanged with
the Rust chain: concurrent updates, tombstones/capacity, real fork cleanup, pipe
close and error/TLS/concurrency checks pass differentially against original C.
Test adapters cover host cerror TLS and fatal abort only; they do not implement
unported emulation, cancellation or server functionality.

A full original system_kernel link now uses the Rust x86_64 source slices with
identical 1,362 public definitions and 18 imports, confirmed original/Rust symbol
provenance and no new stubs or permissive undefined-symbol mode. The i386 final
slice remains original and is byte-identical. Whole-target migration, original
C/assembly retirement, Cargo replacement of that complete original graph and
Darwin process/application execution remain pending.

Additional installed Mac utility and GUI checks
==============================================

Run tools/check_mac_utilities.py through tools/run_isolated_server.py, supplying
--original-kernel, --rust-kernel and a new --output directory. Eight independent
workloads check PlistBuddy edit/read/delete, bsdtar, ditto -rsrc, gzip, bzip2, xz,
zip/unzip and OpenSSL with strict statuses and predetermined output. Every case
uses its own guest temporary directory. All namespaces/prefixes are task-owned.
The installed ditto is a shell wrapper around cp; it is not a native utility or
a migrated implementation. The remaining executables are installed Mac binaries.

Current evidence: seven of eight workloads pass under both kernel variants;
bsdtar crashes while creating an archive on both. Raw evidence and exact input
hashes are referenced in additional-app-verification.json. The first exploratory
run also exposed harness mistakes (unsupported ditto invocation and wrong grep
path), both corrected before recording the seven passing results.

build_gui_apps.py additionally builds Cocotron CGShadingCreate. Its upstream
binary nib encodes object references as literal CF$UID dictionaries, preventing
the sample window from loading. --repair-shading-nib explicitly converts those
to binary plist UID references in the copied resource, with before/after hashes
and conversion count. Source files and reference resources remain untouched.
Regression tests cover conversion, idempotence and rejecting invalid references
without modifying files.

With that resource repair, check_gui_apps.py --cases CGShadingCreate passes under
both kernels on the isolated display. Both screenshots were manually inspected:
the controls and red/black axial gradient render. Radial mode and control actions
are not covered. Existing Calculator/TextEditor checks remain the default. Both
owned prefixes/launchers and the hidden Xephyr display were cleaned up.

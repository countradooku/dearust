Implemented runtime slices
--------------------------
New no_std crates dearust-unlinkat, dearust-linkat and dearust-renameat replace
three x86_64 syscall wrappers. Original atfd/TLS, vchroot and common flag helpers
remain C. The wrappers preserve syscall argument widths/order, Linux syscall
numbers 263/265/264, original int result narrowing, and rename success returning
zero. Source expansion precedes destination expansion and flag validation;
linkat follows the source only with BSD_AT_SYMLINK_FOLLOW, never the destination.
No new policy for the original broadly shared flag converter is invented.

Paths are copied directly into initialized final ABI storage, bounded to 4096
bytes. NULL input returns EFAULT, fixing three actual prior-runtime crashes;
unterminated input returns ENAMETOOLONG. Link/rename require two live paths,
so each retains exactly two final buffers, with no returned-array intermediate.
The original plain unlink/link/rename C wrappers reach these Rust entries and
are not themselves counted as migrated. Invalid non-NULL input pointers retain
the existing in-process caller validity contract. See each crate's SAFETY.txt.

Guest probes validate different source/destination dirfds and cwd, per-thread
AT_FDCWD in both positions, hard-link inode identity, final-symlink follow policy,
rename replacement/content identity, unlink not following targets, directory
removal, errors, null/long paths and preserved unrelated files. Missing dirfd
references retain existing vchroot ENOENT behavior. Some nonexistent paths pass
expansion and reach flag validation before the raw kernel, also as before.
Native fixtures separately inject expansion failures to verify error ordering.

CPU and memory evidence
-----------------------
The ports allocate no heap and introduce no allocator/panic runtime imports.
Generated native local stack subtraction (register pushes/callees excluded):
                       original C       Rust
    unlinkat              4112 B       4112 B
    linkat                8224 B       8216 B
    renameat              8216 B       8216 B

These are frame measurements, not process-RSS claims. All initialized storage
is in place; safety checks and initialization remain explicit.

A real native linkat -> renameat -> unlinkat roundtrip, with unchanged pinned C
sources and explicit native vchroot/TLS/include adapters, measured median CPU
4666.3 -> 4774.1 ns/roundtrip: Rust is 2.31% slower in this workload. Twenty-one
alternating samples, 2000 roundtrips/sample, one eligible CPU; quartiles/raw
samples and exact adapter text are preserved. No native speedup is claimed.

The actual matching guest roundtrip, old/new/new/old process order, 42 samples
per variant and 200 rounds/sample, measured CPU 35.9225 -> 35.9150 us/roundtrip.
CPU quartile ranges overlap; the medians are essentially equal. Wall medians are
36.5325 -> 36.7750 us/roundtrip. This does not demonstrate a meaningful guest
speedup. Native adapters exclude virtual-root/TLS and the local original C raw
entry's tracing wrapper; do not equate those two measurement environments.
Existing RUNTIME-PERFORMANCE.txt measurements remain separate historical evidence.

Confirmed defects and implementation
------------------------------------
The preceding candidate used SIGEV_THREAD. An actual installed-glibc allocation
failure reproduces loss of a one-shot CPU deadline: zero SIGXCPU, last_error zero.
The frozen source witness is glibc04e750e75b73957cf1c791535a3f4319534a52fc;
the actual distro libc is separately hashed/disassembled, not equated to that pin.
The primary source allocates callback data and starts a callback thread at expiry.
Original source URLs/hashes, the failed allocation and recovery are retained.

New tools/resource_cpu_dispatch.inc prepares a shared synchronous receiver,
CLOEXEC/NONBLOCK signalfd and eventfd before accepting a timer. Expiry and rearming
an existing timer allocate nothing and create no threads. Each owner retains one
kernel timer bound to the original task/struct-pid identity. Initial numeric-clock
binding is checked against the original pidfd AFTER unarmed timer_create, before
arming/publication; a raced death fails without publishing the prepared timer.
The host_pid/pidfd pair must name the same original process. The descriptor-only
fd_owner must not own a Process, CpuTimer or Dispatcher, even indirectly.

An opaque, never-reused token identifies that kernel binding, not a generation.
On a matching notification the receiver locks the Arm and queries the exact owned
timer. Nonzero remaining time suppresses an old wake after a later rearm; zero
allows exactly one current delivery. Code/token filtering alone does not prove
kernel-authenticated origin. The bound timer state prevents premature delivery.
Rearm updates physical timer state before nonthrowing generation publication;
failed preparation or replacement retains the prior arm. Disable retires the
binding; terminal shutdown cannot be reopened. Deadlines above signed64 nanoseconds
fail EOVERFLOW rather than inherit Linux's earlier ktime clamp. Existing XNU policy
saturates physical CPU deadlines at INT32_MAX seconds, below that boundary; this
is separate from full logical unsigned-limit ownership, which is unfinished.

The receiver explicitly blocks its reserved RT signal before publishing readiness.
The caller reserves that signal for cooperating dispatchers and preserves its
non-ignored disposition. Shutdown wakes through the precreated eventfd, so it does
not need a fresh RT signal-queue allocation. A failed timer-state query is reported
as a persistent negative diagnostic until explicit successful rearm; automatic
redelivery or retry is not claimed. Full asynchronous fault handling remains open.

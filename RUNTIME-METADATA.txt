Subsystem and behavior
-----------------------
Existing dearust-path now owns fourteen original C source slices/nineteen exported
entries. This batch adds stat/stat64 and fstat/fstat64, and consolidates the prior
lstat/fstatat crates. Workspace packages decrease13 ->11. The two moved metadata
ABI modules are byte-identical to commit5c44951; their duplicate copier tests are
replaced by the existing shared three tests. Logical ABI modules and original C
export names remain. No heap storage, cache or process-global state is introduced.

stat/stat64 read the original thread-cwd bridge BEFORE delegating to sibling
fstatat/fstatat64 with flags0, retaining guest TLS ordering even for NULL inputs.
They follow final symlinks and reuse the existing initialized in-place4096-byte
path and144-byte Linux metadata buffers, with no additional path copy/buffer.
fstat/fstat64 sign-extend the C int descriptor to raw Linux syscall5, initialize
144 bytes aligned to8, narrow the raw result to C int before its sign check, and
convert errors once. Successful calls use the original C stat_linux_to_bsd/64
converters. Darwin layouts, UID/GID policy and conversion remain original C.

Confirmed defect fixed: valid-fd NULL-output fstat previously crashes in the
converter; it now returns EFAULT. Kernel errors retain precedence, so an invalid
fd with NULL output still returns EBADF. Both errors leave caller output untouched.
The new fstat guest probe exits139 on the previous kernel and passes with Rust.
Non-NULL pointers retain the existing readable/writable/aligned caller contract;
arbitrary invalid addresses are not newly fault-safe. Previous bounded-path and
flag/virtual-root policies remain. See both safety ledgers in crates/dearust-path.

paths.o now replaces14 unique original link inputs and appears once in each
response. Use --paths-object and the corresponding original --lstat-bridge;
remove --lstat-object and --fstatat-object. Mixing grouped and individual pathname
or metadata switches is rejected. Historical individual switches remain usable
with historical artifacts. Preserve matching/pinned TLS/fork bridge separation,
--fd-object and --process-ids-object; process queries stay matching-only.

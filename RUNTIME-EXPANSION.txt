Dearust runtime expansion: guarded descriptors, process info and lstat
===================================================================

Project owner: @countradooku. Implemented and reviewed using OpenAI Codex AI
assistance. See runtime-expansion-verification.json for exact artifact hashes,
original comparisons, native sanitizer evidence and raw test record locations.

New runtime work
----------------
The allocation-free dearust-guarded crate replaces the fixed descriptor table.
It rejects negative descriptors, fixing original sentinel aliasing and a
reproducible ASan global-buffer-overflow after capacity is reached. Fork cleanup
removes an entry before invoking its callback, preserving callback reinsertion.
Private prepare/parent hooks serialize the table snapshot around fork and release
the parent lock on both success and failure. The small copied fork.c bridge
preserves each original backend and child RPC lifecycle. Native tests include
100 forks during active table mutation and a real forced fork failure.

dearust-process now handles SHORTBSDINFO, TBSDINFO, TASKINFO and TASKALLINFO in
Rust. Fixes include target-process credentials, the public LP64 bit, short-info
return length, RSS bytes, CPU nanoseconds and names containing ')'. Output is
transactional and buffer bounds are tested. Remaining accounting limitations
and original fallback flavors are documented in the crate's SAFETY.txt. Target
lookup retains Darling's existing access model, not macOS authorization parity.

dearust-lstat replaces both lstat wrappers. The original lstat64 dereferences a
null pathname during an actual bsdtar archive operation; Rust returns EFAULT.
Both wrappers reject null outputs and limit pathname copying to 4096 bytes,
returning ENAMETOOLONG rather than overflowing. Existing vchroot and stat
conversion routines remain C. A tiny C bridge preserves the original thread
working-directory TLS accessor. Invalid non-null pointers are outside the
existing caller safety contract; this is not a general guest memory validator.

The upstream CGShadingCreate sample had malformed binary nib object references.
build_gui_apps.py --repair-shading-nib repairs copied resources explicitly and
records before/after hashes. The source executable and upstream tree are intact.
A Calculator screenshot race is fixed by waiting for painting before capture.

Reproduction
------------
From the repository, set MATCH_SOURCE and MATCH_BUILD to the matching Darling
source/build, SERVER to the rebuilt Rust-lockset server, and WORK to a new owned
output directory outside those reference trees. See LOCKSET-PROCESS.txt for
server build instructions. Every build helper refuses reference-tree output.

    cargo xtask check
    python3 -m unittest discover -s tools -p 'test_*.py'
    cargo test -p dearust-xtask --test runtime --offline --locked -- --ignored
    cargo xtask runtime --target x86_64-apple-darwin --destdir "$WORK/runtime"
    python3 tools/build_lstat_bridge.py --build "$MATCH_BUILD" --output "$WORK/lstat-bridge"
    python3 tools/build_guarded_fork_bridge.py --source "$MATCH_SOURCE" --build "$MATCH_BUILD" --output "$WORK/fork-bridge"
    python3 tools/relink_matching_kernel.py --build "$MATCH_BUILD" --runtime "$WORK/runtime" --process-object "$WORK/runtime/objects/process.o" --guarded-object "$WORK/runtime/objects/guarded.o" --fork-object "$WORK/fork-bridge/fork.c.o" --lstat-object "$WORK/runtime/objects/lstat.o" --lstat-bridge "$WORK/lstat-bridge/lstat-bridge.o" --output "$WORK/kernel"
    python3 tools/run_isolated_server.py --server "$SERVER" -- python3 tools/check_mac_utilities.py --original-kernel "$WORK/kernel/libsystem_kernel-original.dylib" --rust-kernel "$WORK/kernel/libsystem_kernel-rust.dylib" --output "$WORK/utilities"

Use build_runtime_probes.py to compile tools/fixtures/{process-info,lstat-regression,
guarded-fork}.c with matching headers and installed SDK; check_mac_apps.py runs
those binaries with explicit expected outputs. GUI build/run commands are in
ADDITIONAL-APPS.txt and GUI-VERIFICATION.txt. Only an explicitly owned hidden X
display is used. Original expected failures make comparison runners exit nonzero;
inspect each variant instead of treating the overall exit as a Rust failure.

Continuation: mapped pathnames and sixteen utility workloads
----------------------------------------------------------
The Rust region queries now recover exact filenames containing newlines from
/proc/PID/map_files/START-END. Linux maps text represents newline as literal
\012, which previously caused wrong paths and overlay device identity. The
actual guest regression fails under the previous Rust kernel and passes under
the new one for both REGIONPATHINFO and REGIONPATHINFO2, testing real newline,
literal \012 and ordinary backslash names. Access-denied fallback ambiguity and
concurrent procfs races remain documented in dearust-process/SAFETY.txt.

Utility coverage expands from eight to sixteen workloads: cpio archive roundtrip,
awk aggregation, sed transformation, bc/dc arithmetic, diff/patch apply/reverse,
sort and find join the previous eight. All sixteen pass the final Rust kernel;
original C bsdtar and cpio crash with exit 139 while its other fourteen pass.
This comparison establishes observed workload behavior, not a new cpio root-cause
diagnosis or arbitrary application compatibility.

108 Rust tests, 29 Python tests, formatting, strict Clippy and the explicit Darwin
artifact ABI/staging check pass. The matching final link preserves 1370 public
definitions and 40 imports. All four guest probes pass; existing 29 app checks
retain 28 exact passes plus the explicit cfbridge timestamp normalization.
